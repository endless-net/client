# EndlessNet v0.6.0

This release advances the client migration to the Protobuf `client.v0` local
API. It does not mark the complete BA/SA runtime cutover as accepted.

## Changes

- Native agent, CLI and recovery helper use the generated local API over Unix
  sockets or Windows named pipes, with bootstrap pairing and peer authorization.
- Network selection now runs through a durable worker: authorized catalog
  preparation, isolated registration, approval refresh, source teardown, target
  activation and apply. Recovery retains uncertain work and compensates only
  the isolated target without logging out the shared account session.
- Temporary network registration, map refresh and cleanup failures retain the
  operation for retry; completed requests can be replayed after worker shutdown.
- Enrollment checkpoints retain credential signing trust. Signed source-map
  observations can refresh during selection without accepting policy or identity
  changes as equivalent source state.
- Desktop lifecycle preferences persist KEEP_INTENT defaults, and Windows
  lifecycle delivery copies native control data before callback return.
- DNS TCP/UDP listener selection tries independent dynamic-port candidates
  within a bounded attempt count to avoid contiguous Windows port exclusions.
- Windows state readers tolerate brief sharing violations during atomic state
  replacement, so concurrent service updates do not fail fresh CLI requests.

## Compatibility and limits

Local consumers must use the matching `client.v0` contract and bootstrap pairing.
The inspected native runtime paths do not provide an HTTP IPC v2 fallback.
This release does not establish compatibility with an older UI distribution.

The complete runtime, exit/resource effects, lifecycle/platform qualification,
permanent-error recovery and external backend/UI acceptance still have open
requirements. See the [runtime requirement and evidence matrix](https://github.com/endless-net/client/blob/v0.6.0/docs/client-runtime-implementation-gaps.md)
and [cutover ledger](https://github.com/endless-net/client/blob/v0.6.0/docs/client-ipc-cutover.md).

Artifacts include client/recovery-helper binaries, the local API descriptor,
manifests, checksums and build attestations from the client release workflow.
Debian packages are published through the APT workflow.
